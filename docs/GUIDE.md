# 第一部分 · 用户篇

## 1. 这是什么

「如果人生有系统」是一个住在网页里的成长系统。它借用了系统流小说的"金手指"框架——但给不出凭空的奖励：**你看到的所有升级，都来自你真实的行为积累**。系统做的事只有三件：

1. 让你的努力**可见**（等级、进度条、成长档案）
2. 给你**反馈**（打卡动画、升级高光、随缘彩蛋、挑战仪式感）
3. 陪你一程（呆呆的、有点社恐、偶尔玩梗的观察者人格「六六」）

## 2. 启动它

```bash
cd xiaoban      # 进入项目文件夹
npm install     # 仅第一次需要（需已安装 Node.js ≥ 18）
npm start       # 启动
```

浏览器打开 **http://localhost:3000**，底部状态条显示"已连接 🟢"即成功。

- 改代码后自动重启：用 `npm run dev`
- 重置存档：删除 `server/data/runtime/state.json` 后重启
- 所有数据只存在你自己的电脑上，不联网、不上传

## 3. 面板页：四大类 · 属性 · 两种打卡点

面板页是系统的主界面，结构是**大类 → 属性 → 打卡点**（属性设计出自《功能设想.txt》）：

```
🫀 身体健康 ── 🌙 体魄与作息
🧠 学习能力 ── 🎤 表达与沟通
🔥 科学减脂 ── ⚡ 能量与代谢
📚 认知成长 ── 🎯 专注与深度输入
```

### 3.1 日常积木：具体的小事

每个属性由 3 个**具体、可衡量、当天可完成**的行为积木喂养：

| 属性 | 日常积木 | 单次 EXP | 每日上限 |
|---|---|---|---|
| 🌙 体魄与作息 | 😴 黄金睡眠：23:00前入睡且睡满7.5小时 | 25 | 1次 |
| 🌙 体魄与作息 | 💧 水分补给：全天饮水1500ml以上 | 15 | 1次 |
| 🌙 体魄与作息 | 🧘 体态矫正：10分钟脊柱拉伸/肩颈放松 | 20 | 2次 |
| 🎤 表达与沟通 | 🎤 即兴演讲：无草稿清晰讲述一个观点2分钟 | 25 | 2次 |
| 🎤 表达与沟通 | 📖 高效输入：深度朗读优质文章5分钟 | 15 | 2次 |
| 🎤 表达与沟通 | 💬 复盘总结：一次高质量的主动沟通 | 20 | 1次 |
| ⚡ 能量与代谢 | 🥗 控卡饮食：至少一餐高蛋白低碳水 | 20 | 2次 |
| ⚡ 能量与代谢 | 🏃 有氧燃脂：20分钟以上有氧或快走 | 25 | 1次 |
| ⚡ 能量与代谢 | 🍏 拒绝加餐：成功抵御一次高糖零食诱惑 | 15 | 1次 |
| 🎯 专注与深度输入 | 📵 无手机时刻：专注模式45分钟不碰手机 | 25 | 2次 |
| 🎯 专注与深度输入 | 📚 深度阅读：无干扰连续阅读20分钟 | 20 | 2次 |
| 🎯 专注与深度输入 | ✍️ 复盘输出：写一段深度思考或日记 | 15 | 1次 |

规则：每日上限防刷分（一天做10次运动≠10倍健康）；升级所需 EXP 逐级 ×1.5 递增；复杂度永远藏在后台，你只看等级、进度条、打卡按钮。

### 3.2 挑战任务：走出舒适区的大事 🎖

每个属性还有一条**挑战线**——系统按序发布的阶段性大事件：

- 体魄与作息：黄金睡眠七连击（+100）→ 固定作息实验（+150）→ 体态纪录片之月（+200）
- 表达与沟通：3分钟即兴演讲（+120）→ 倾听者之日（+100）→ 公开表达实战场（+200）
- 能量与代谢：燃脂一周目（+100）→ 控卡七天挑战（+120）→ 体脂里程碑（+250）
- 专注与深度输入：90分钟深度工作（+120）→ 啃完一本硬书（+200）→ 离线星期日（+150）

规则：
- 一次只有一个进行中的挑战，完成后**大额一次性 EXP**
- 完成后系统进入 **3 天"筹备中"**，下一个挑战才会发布——挑战是稀缺的，才值得被记住
- 完成时需要**确认弹窗**（"确定你已经真的做到了？"）——这是对自己诚实的仪式
- 挑战会记入成长档案，六六也会专门祝贺你

### 3.3 顶部系统横幅

面板顶部的 SYSTEM 横幅显示日期、**连续打卡天数**、今日打卡次数——你的坚持，系统一直在看。

## 4. 聊天页：与六六对话

「六六」是系统人格（观察者 + 轻度社交尴尬 + 偶尔玩梗）：

- **它读得懂面板**：问"我今天表现怎么样"，会用真实数据回答（属性等级、进度、今日次数、连续天数、进行中的挑战）
- **它看得见打卡**：面板打卡/完成挑战后切到聊天页，它会主动冒出来吐槽或祝贺
- **它会接住情绪**：说"好累""坚持不下去了"，它会笨拙但真诚地开解
- **日常闲聊**：问它"你是谁"、说"谢谢"，或随便聊

🧹 清空对话重新开始。

## 5. 彩蛋通道：随缘的惊喜 🎁

聊天页输入栏旁的 🎁 ——汇报一件**清单之外的即兴好事**，六六"看心情"给奖：

- 可能是**额外 EXP**（流向你今天最没照顾到的属性），也可能是**稀有勋章**（挂上面板勋章墙），也可能"缘分未到"
- 每天最多成功 2 次 · 成功后 10 分钟冷却 · 约 75% 命中 · 连续 3 次落空后必中
- 勋章共 5 枚：🍀即兴好事、📜生活诗人、🤝微光善举、🔭好奇心旺盛、🎪给自己惊喜

> 设计红线：彩蛋刻意稀缺，所以永远不会污染主积分的可信度。

## 6. 常见问题

**Q：打卡错了能撤销吗？** 目前不能。存档是本地 JSON（`server/data/runtime/state.json`），懂技术可手动改。
**Q：换电脑数据会丢吗？** 会。把 `server/data/runtime/` 整个文件夹拷走即可迁移。
**Q：AI 是真的 AI 吗？** 默认是本地模板（离线可用）。设 `AI_API_KEY` 环境变量即可切真实大模型，见开发者篇 §3。
**Q：等级有上限吗？** 没有。曲线后期增长很快，够用很多年。
**Q：长时间不打卡会怎样？** 见 §7 衰减机制——属性会"掉 EXP"，但永不掉级、永不归零。

## 7. 属性衰减与警告机制（不进则退）

系统流小说的规则在这里也成立：**属性放久了会掉**。

| 闲置时长 | 系统行为 |
|---|---|
| < 24小时 | 一切正常 |
| 24~48小时 | 属性卡出现轻微提醒状态 |
| 48~72小时 | 卡片边框变橙 + ⚠"XX小时未维护"徽章（临近衰减） |
| **超过72小时** | **衰减执行**：卡片变红呼吸灯 + ⚠"衰减中" + 机械腔警告弹出 |
| 持续闲置 | 每24小时再扣一次，直到你回来维护 |

**衰减规则**：每次扣除 `当前EXP × 5% + 10`（单次上限40）。

**保护机制**（不制造绝望感）：
- **Lv.1 的属性永不衰减**——新手期是安全的
- **EXP 不会被扣穿**，更**永不掉级**——衰减只影响进度条，不抹掉已达成的等级
- 从未打卡过的新属性不衰减

衰减时，六六会切换成**机械冷酷腔**（"【警告】宿主【体魄与作息】属性长期未维护，数值发生衰减 -16 EXP。请立即处理。"）——与日常的呆萌吐槽形成反差，这就是系统的压迫感。衰减事件也会记入成长档案（红色条目），让你看清自己懈怠的历史。

# 第二部分 · 开发者篇

## 1. 技术栈与架构总览

```
Node.js (≥18, ESM) + Express 5          ← 后端
原生 HTML/CSS/JS (ES Modules, 无框架无构建) ← 前端
JSON 文件 (server/data/runtime/)        ← 存储
```

单语言全栈、零构建步骤、存储可替换。唯一生产依赖 express。

**分层铁律**：
- `routes/` 只做参数校验和调 service，不写业务逻辑
- `services/` 不碰 HTTP 对象；磁盘 IO 只存在于 storage.js
- 前端任何页面都通过 `api.js` 发请求

## 2. 数据模型：三类成长单位

```
seedCategories[]                 大类（身体健康/学习能力/科学减脂/认知成长）
  └ attributes[]                 属性（体魄与作息/表达与沟通/能量与代谢/专注与深度输入）
      ├ dailyBlocks[]            日常积木：{id, name, icon, exp, dailyLimit}
      └ challenges[]             挑战池：{id, name, desc, exp}，按序发布
```

**新增属性/积木/挑战只改 `server/data/seed/attributes.js` 一个文件**，面板渲染、限额、升级、彩蛋注入、六六的数据播报全链路自动生效。

运行时状态（state.json）与设定分离：

```jsonc
{
  "attributes": { "vision": {"level":1,"exp":0}, "english": {...} },
  "blockLogs": { "2026-08-31": {"carrot":1} },       // 每日流水，90天滚动清理
  "challenges": { "english": {"index":1, "completedName":"…", "revealedAt":"2026-09-03"} },
  "timeline": [...], "chatHistory": [...], "medals": [...],
  "eggLogs": {...}, "lastEggAt": 0, "eggFailStreak": 0
}
```

## 3. 接入真实大模型（可选）

```bash
set AI_PROVIDER=anthropic      # 或 openai
set AI_API_KEY=sk-ant-xxxx
npm start
```

- 配置后：persona.js 的 System Prompt + 面板实时摘要（含挑战状态）随每次请求注入

## 4. 核心数据流

### 4.1 日常打卡 → 升级
```
POST /api/panel/feed {blockId}
  → findBlock(seed) → 每日限额检查 → applyExp(纯函数：注EXP+升级进位)
  → 记流水 → levelUps>0 记时间线 → 落盘
前端：局部刷新进度条/等级 → 升级弹窗 or toast → store.set('feedEvent') 广播
聊天页监听 → 六六主动吐槽/祝贺（打字机气泡）
```

### 4.2 挑战任务（状态机）
```
每属性独立推进：pool[index]
  published（可完成）→ POST /api/panel/challenge/complete
    → 大额EXP注入 → index+1 → revealedAt = 今天+3天（冷却）→ 记时间线 → 落盘
  locked（筹备中）→ 面板显示倒计时；重复完成请求 → 429 CHALLENGE_LOCKED
  冷却到期 → 面板组装时自动切回 published（幂等，重启安全）
  池见底 → empty（"日常积木就是你的主战场"）
```

### 4.3 属性衰减（懒结算模式）
```
getPanel() 被调用（打开面板/打卡后刷新）
  → runDecaySettlement()：
     对每个开放属性：
       1. hoursSinceLastFeed：从 blockLogs 算闲置时长（按属性下全部积木）
       2. computeDecay 纯函数判定：
          - Lv.1 / EXP≤0 / 从未打卡 → 保护，跳过
          - 闲置 < 72h → 不衰减
          - 闲置 ≥ 72h 且距上次结算 ≥ 24h → 扣 min(当前EXP×5%+10, 40, 当前EXP)
       3. 命中：扣EXP + lastDecayAt 更新 + 时间线归档(type:'decay')
  ← panel.decayEvents[] 随面板数据下发
前端：机械腔警告 toast（等宽字体、琥珀色） + 属性卡警示样式(danger呼吸灯)
     + store.set('feedEvent', {type:'decay'}) → 六六切冷酷腔补刀
无定时器、无后台任务：全部在请求路径内完成，服务器重启零状态丢失
（lastDecayAt 节流保证幂等——同一次闲置不会被重复结算）
```

### 4.4 聊天 → 回复
```
POST /api/chat/send {text}
  → LLM 配置？ 是：systemPrompt+panelDigest(实时数据含挑战) → LLM（失败自动降级）
              否：reply-engine 意图识别（问候/进度/情绪/介绍/兜底）
前端："正在输入"动效 → 打字机逐字显示
```

### 4.5 跨页事件（无框架事件总线）
```
store.set('feedEvent'|'eggEvent', payload)   ← 面板页/彩蛋弹窗
store.subscribe(key, handler)                ← 聊天页/面板页
store 是模块级单例，页面切换不销毁 → "面板打卡→切聊天页被六六调侃"闭环成立
```

## 5. 调参与扩展指南

- 积木块/挑战定义 → `seed/attributes.js`
- 升级曲线 → `progression.js`（BASE_EXP、GROWTH）
- 挑战冷却天数 → `progress-service.js` 顶部 `CHALLENGE_COOLDOWN_DAYS`
- 彩蛋手感 → `easter-egg-service.js` 的 `EGG_CONFIG`
- **衰减手感（宽限期/扣减比例/上下限）→ `decay-service.js` 的 `DECAY_CONFIG`**
- 六六台词（对话）→ `ai/persona.js`；（打卡即时反应）→ `public/js/pages/chat-reactions.js`（含衰减冷酷腔 `DECAY_REACTIONS`）
- 新功能：`services/xxx.js` → `routes/xxx.js` 一行挂载 → `api.js` 加方法，三步不碰旧代码
- 换数据库：只重写 `storage.js` 的导出函数

## 6. API 一览

| 方法 | 路径 | 作用 |

## 7. 已知边界

- 单用户设计（无登录/多用户隔离）——个人工具定位
- 存档同步写盘——单用户低频无压力
- 打卡依赖自觉（诚信打卡是产品哲学：不为刷分的人设计防刷分，为不刷分的人保留自由）
- 挑战完成的真实性依赖确认弹窗的自觉——同上
